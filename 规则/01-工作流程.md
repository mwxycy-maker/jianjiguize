# 01 工作流程

来源：DeepSeek 三模型 PK 那期（2026-10）实际走通的流程。

## 开工前：先对齐，再动手

1. **读分镜表、读素材清单，把疑问一次问完。** 那期开工前问了 7 个问题（数据在哪、字幕以稿子还是实际说的为准、某段音频当背景音还是删掉、徽章叫什么……），阿亮一次答完，后面基本没返工。问之前先自己看完所有素材，问题要具体到「第几镜、哪个文件」。
2. **确认交付形式。** 阿亮默认要 **HTML 网页预览**（浏览器打开能播、能拖进度条）。没有明确说，不导出 MP4。
3. **确认主角。** PK 类视频要先确认谁是主角，主角的出场、特写、胜利时刻都要多给一点戏。
4. **确认模型/产品的显示名。** 徽章上的名字以阿亮给的为准（那期：DeepSeek V4.1 Flash、GPT-6.1 Sol、Claude Opus 5.5、GPT-6 Astra）。

## 沟通约定

- 阿亮说「第 N 段」，指的是**网页预览进度条上的分段序号**（也就是第 N 个镜头），不是分镜表的行号。改之前先把序号对上镜头内容，再回复确认是哪一处。
- 阿亮说「先纯 Aroll，在 xx 处开始用素材」，就是这一句之前全屏口播，说到 xx 时头像缩回圆窗、素材同时进场。

## 分镜和交付（2026-10 鹈鹕测试重剪补充）

- **分镜不用写太细**：几句话说清每段做什么，再配一张示意图（真实素材帧 + 新视觉规范拼成的静帧，每段一张 4 格）。阿亮直接在图上指出要改的镜头，比逐镜表格快得多。
- **先交前 30 秒定方向**，阿亮说「直接做完成片」再一次做完。
- **默认交网页工程，不渲染 MP4**。那期做完曾经开始导出，阿亮：「不用渲染，你把这个剪辑工程上传到 github 仓库里」。
- **上传到当期视频仓库时只传「剪辑工程 + 配乐」**：工程代码、素材、音效、字体、混好的音轨（`mix.m4a`）和 `音乐/` 下的歌（阿亮有版权）。临时脚本、审片截图、导出用的副本都不传（阿亮：「那些脚本不用」「只需要配乐和剪辑工程」）。`mix.wav` 能重新生成，也不传。
- **做完要合进主分支**：仓库首页默认显示 main，只推到分支上阿亮在首页看不到。推完开 PR 并合并到 main。

## 动画片段用 HyperFrames（阿亮 2026-10-23）

- **以后的动画片段都用 [HyperFrames](https://github.com/heygen-com/hyperframes) 做**：花字、图标动效、信息图、标题、转场这类动画，每段写成一个 HyperFrames composition（HTML + GSAP）。做法和云端环境准备见 [HyperFrames模板/](../HyperFrames模板/README.md)。
- **先看 HTML，不先渲染**：做好的片段先用 `hf_preview.py` 生成 HTML 预览页发给阿亮，**播放器用之前的工作台播放器 1.0**（分段进度条、▶ 播放、逐帧、倍速、逐字稿栏，和整片预览一样），不另做简易控件；阿亮确认没问题、要出成片时，才渲染成 MP4 或透明 WebM 放进工程。
- 口播剪辑、字幕、混音、网页预览仍按原流程。

## 制作顺序

| 步骤 | 做什么 | 工具 |
|---|---|---|
| 1 | 口播转写，拿到逐字时间戳和停顿表 | `工具/transcribe.py` |
| 2 | 人工校对稿子，按字幕断句（`|` 分隔），写进 `lines.py` | 手工 |
| 3 | 生成时间线：压缩长停顿、插入 MV/大标题的停留、对齐字幕 | `工具/timeline.py` |
| 4 | 把模型生成的 HTML 演示逐帧录成视频素材（统一机位） | `工具/record_html.py` |
| 5 | 需要「字在人后面」时，做人物抠像 | `工具/matte.py` |
| 6 | 写每一镜的动画（纯函数 `renderAt(t)`） | `组件/动效组件.js` |
| 7 | 选歌、分析鼓点、写配乐表和音效表 | `工具/beats.py`、`工具/示例_cues.py` |
| 8 | 混音：人声 -16 LUFS、音乐自动闪避、整片 -14 LUFS | `工具/mix.py` |
| 9 | 截静帧自查，每段都看 | `工具/stills.py` |
| 10 | 打包网页预览发给阿亮 | `工具/preview_build.py` |

## 节奏：一段一段交

- **先交前一两段**，让阿亮定方向，再往下做。那期先交了第①②段，阿亮给了一整轮反馈（花字、画幅、构图、3D 视角），后面的段落直接按新要求做，省了大量返工。
- 每段做完先自己截静帧看一遍：字有没有被挡、框有没有出画、数据水印有没有溢出、主持人圆窗有没有压内容。
- 后台任务（录制、渲染）要告诉阿亮大概还要多久；做完一组接一组，最后发完整预览。

## 自查清单（每段交之前）

- [ ] 画面和口播对得上，口播点到什么，画面才出现什么，不提前剧透。
- [ ] 字幕和实际说的话一致（不是和稿子一致）。
- [ ] 没有超过 0.5 秒的空停顿（除非是故意留的笑点停顿）。
- [ ] 同一组演示的角度、方向、出场时间一致。
- [ ] 新元素出现时重新构图，没有元素互相压着。
- [ ] 数据水印没有超出画框。
- [ ] 换段落时 BGM 跟着换，衔接按 02 的方法。
- [ ] 音效不过量：每个音效都对应一个画面动作。
