# 05 口播与字幕

来源：DeepSeek 三模型 PK 那期（2026-10）。

## 一、转写

- 用离线的 **sherpa-onnx + SenseVoice（int8）+ Silero VAD**，中英混说也认得准，还能给出逐 token 时间戳。脚本：[工具/transcribe.py](../工具/transcribe.py)。
- 识别结果一定会错专有名词（那期「DeepSeek」被认成「deepse」「dep」，「GPT-6.1」认成「JbD6.1」，「Vibe Coding」认成「web coding」）。**人工校对后写进 `lines.py`**，时间戳仍然用识别出来的，用 `difflib` 把校对稿逐字对齐到识别结果上（[工具/timeline.py](../工具/timeline.py) 的 `char_times`）。

## 二、字幕

1. **字幕以实际说出的为主**，不以稿子为准。口播说了「Vibe Coding」，字幕就写 Vibe Coding。
2. 用 `|` 在 `lines.py` 里手动断句。每条字幕一口气能读完，不跨语义断。
3. 太短的碎句合并（那期合并过「怎么样 你猜对了没」「也有 那就是搜得快 没广告」）。
4. 字幕出现比开口早 0.06 秒，结束在下一条开始前 0.04 秒，最短显示 0.22 秒；相邻字幕不重叠。
5. 专有名词统一写法：产品名按官方或阿亮给的写（DeepSeek V4.1 Flash、GPT-6.1 Sol、Claude Opus 5.5）。

## 三、剪停顿

1. **超过 0.5 秒的停顿要压缩**（阿亮同意）。只剪停顿、不剪字。
2. 压缩后保留：上一句尾 0.17 秒 + 下一句前 0.15 秒，听起来自然、不赶。
3. 故意留的停顿（笑点、大标题、MV 完整播放）用 `HOLDS` 插入额外时长，不靠原始停顿：
   ```python
   HOLDS = {
       18.59: 0.55,          # 「谁将更胜一筹」后：VS 重击 + 换歌
       38.40: 24.30 + 1.70,  # 「分别对应哪个模型」后：三条 MV 完整播放 + 揭晓
   }
   ```
4. 时间映射用分段表 `pieces = [源入, 源出, 成片入]`，画面里的口播视频、混音里的人声、字幕都用同一张表，三者永远同步。插入段里口播画面冻结在上一段末尾。

## 四、事件锚点

所有画面动作挂在「第几句 + 哪个词」上：

```python
EV = {
  'ds_front4': A(8, '整体效果'),       # 第 8 句「整体效果」开口那一刻
  'first':     A(9, '第一名') - .35,   # 提前 0.35 秒（动画要先动，观众听到词时动作刚好到位）
  'stores_out': A(10, '自反馈') - 1.0,
}
```

- `A(i, 词)`：开口时刻；`AE(i, 词)`：大致说完的时刻。
- **动作一般比词提前 0.1~0.35 秒**：入场动画需要时间，观众听到词时画面刚好到位。重击和词同一帧。

## 五、主播口播画面

- 源片上下有黑边的，先裁掉（那期 `AR_CROP = [0, 10, 854, 462]`）。
- 480p 的口播素材全屏也能用（阿亮确认过），但缩成圆窗时清晰度更好看。
